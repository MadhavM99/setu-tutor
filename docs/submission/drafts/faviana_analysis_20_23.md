## Task 21: qualitative examples

Five examples, three of them failures. Each is a case the filters or the checker handled, so the learner never saw a
failing sentence.

1. **Success, live app.** The model wrote "నేను నహీ వెళ్తా ను" ("I won't go", with Hindi नहीं used for the Telugu
   negative). That is exactly the planted mistake. It passed the leak filter and was shown. 13.7 s, 160 tokens
   (mid-submission report, section 6.4).
2. **Retrieval miss.** Raju's "క్యా నువ్వు వస్తావు" (a yes/no question with Hindi क्या) retrieved HI-TE-009 first (0.82)
   and the right rule HI-TE-001 second (0.78). 8 of the 13 top-1 misses went to a TE→HI rule that shares Telugu
   words with the query (`rag_eval_retrieval.md`).
3. **A hint the learner cannot use.** 8 of the 20 hints RAG showed said to read a numbered rule, for example
   "…नियम 2 को पढ़कर देखें…". The learner never sees the numbered list. The fix (never name a rule by number) lifted
   shown-and-usable from 12/29 to 25/29, but it was designed after seeing the same 29 cases (`rag_eval.md`).
4. **Wrong script from a small model.** For HI-TE-001-a, untuned Gemma-3-1B wrote "कै క్యా నువ్వు వస్తావు", which
   adds a Devanagari word. The filter rejected it (WRONG_SCRIPT, NOT_ONE_ERROR) and the app showed the bank sentence
   (`ft_eval.md`).
5. **Not exactly one error.** Prompted Gemini wrote "నేను రాను కాదు", adding a negation to a verb that is already
   negative, instead of the bank's "నేను వస్తాను కాదు". The filter rejected it (`ft_eval.md`).

## Task 22: failure analysis per capability

- **Raju generation (6).** Even the best method fails on 2 of 29 cases (valid 0.93), and the plain methods fail on
  7–8 (0.72–0.76). Resampling did not beat a single call (valid 0.76 vs 0.72; draft leak rate 0.17 vs 0.10), so asking
  again without telling the model why is not worth the extra calls. The agentic method fixes this at 7.5 times the
  tokens per case (1,054 vs 140). Planting precision is 1.00 for every method: when a draft passes, it carries the
  planted mistake. Check the definition of "answer leak" in `setu/research/generation_baselines.py` before quoting it
  as a pre-filter rate.
- **Coach hints (6).** Only 0.41 [0.26, 0.59] of model hints were shown. The filter dropped the rest: 0.34 had Telugu
  in them and 0.31 were not Hindi. No shown hint leaked the answer (0.00 [0.00, 0.12]). The generic hint covers the
  gap, so the cost is hint quality, not safety.
- **Tool calling (14).** 44 tool calls over 29 cases, all correct. Two limits: recovery was "not measurable" because
  no erroneous call occurred, and the attack sets are small (17 harness attacks, 11 injected messages), so "0
  unsafe" has an upper bound of 0.08 to 0.26.
- **Reasoning (15).** Stepwise reasoning did not help: final accuracy 0.36 vs 0.40 for direct (p = 0.625) at four
  times the tokens. Self-check revised only 3.4% of cases, fixed none and broke two. Accuracy on partial answers
  ("fragment") is 0.07–0.10 for every method, which is the same weakness the checker has (below).
- **Checker and judge, including M-09 (13).** On 50 native-labelled answers the checker agrees with the human labels
  at κ = 0.15 (accuracy 0.36 [0.24, 0.50]) and the prompt-only judge at κ = 0.46 (0.62 [0.48, 0.74]). 26 of the 50
  labels are "partial", the class the checker handles worst. **M-09 (the checker says "unsure" on answers whose
  right label is known) is 12/66 = 0.18 [0.11, 0.29] against a ceiling of 0.15, a fail** on the frozen held-out
  cases (`scorecard-2026-10-31-heldout.md`). We did not loosen the ceiling or tune the checker on those cases. An
  "unsure" answer never changes the learner's record: it goes to a teacher. The open decision is whether to count
  incomplete answers as wrong once teacher labels support it. All of these cases are team-generated, so M-09 is
  probably better here than it would be on real learner input.
- **RAG (16).** Retrieval gets the right rule first in 16/29 = 0.55 [0.38, 0.72] and in the top 3 in 24/29. On
  shown-and-usable hints RAG did not beat blind (p = 0.79). Abstention never fires on correct sentences (0/29),
  because a correct sentence matches the same rule as its wrong version. Deciding whether a sentence is wrong stays
  the checker's job.
- **Fine-tuning (10, 17).** No-go: 23 accepted training pairs covering 2 of 14 trainable rules, against a bar of 200
  pairs and 12 rules. The data, not the compute, was the blocker. Untuned Gemma-3-1B passed the filter on 7/29, and
  prompted Gemini on 21/29.
- **Multi-agent vs single agent (18).** The two setups are indistinguishable on accuracy (handling right 1.00 vs
  0.99) and task success (0.31 vs 0.31). Single-agent Raju was valid more often (0.90 vs 0.76). The multi-agent gain
  is structural: 0 model-decided verdicts against 65, at 359 vs 1,682 tokens per case. It is a safety and cost
  argument, not an accuracy one.
- **UI additions (voice, pictures, match game, learning path).** None of this is measured. The simulators do not
  model it and no real learner has used it, so the report should list it under "built, not evaluated".
